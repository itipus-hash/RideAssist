## 彦阳 BLE 协议（反编译定案，勿再猜）

**完整 0xA0 / 163B 偏移表在 `PROTOCOL_FIELDS.md`（第 250–300 行，已逐项与官方截图对账）。
这里只留"会踩错"的部分：**

权威 `reverse/out/sources/com/yybms/`，类 `BMSDataClass`；入口 `InfoActivity_YY`，走 inuker 库。
死代码别研究：`BluetoothLeService`（从未实例化）、`polidea.rxandroidble2`（完全未用）。
寄存器**大端**；回包总长 = `data_len*2+5` 用于识别帧类型；`ByteReader(frame,3)` 已跳 3 字节头，
**官方偏移照抄，不要再 +3**。paramB 标志 `0x4D444253`；`[149]`=batType、`[148]`=串数信息。

- 官方 `byte2shortB` = `(pos+1)<<8 | pos`，等价我方 `le16()`；**但 `[88]` MOS 温度是 u8 单字节**
  （+40 偏移，实测字节 `88:135, 89:125` → 只用低字节 = 95℃）。jadx 把它还原成 `(short)` 是**误译**，
  按 le16 算会得到 32095℃。同类"算出荒谬值"先怀疑反编译器。
- `[70]` = **放电过流二级**，不是恢复阈值 —— 0xA0 帧**没有**放电过流恢复字段。
- 总压阈值 `[36/38]` `[42/44]` 是 **÷100 → V**（曾按 ÷10 算，得出"固件未配置、读 0"的错误结论；
  实机 71.4V / 51.0V = 17×4.2 / 17×3.0，**偏移一直是对的**）。
- 温度类 `[80~88]` **存 +40 偏移，显示须 −40**；充电过流 `[62]` 官方存**负值**；
  短路电流 `[92]` **原值即 A 不缩放**（实测 888A）。
- 163B 设备信息帧：`[38..73]` 36B ASCII = 产品型号；`[80..91]` 是**另一条** 12B `devName`，别混用。
  版本三件套位宽/除数各不同：HW `le16(74)÷100`、Boot `u8(122)÷100`、SW `u8(123)÷100`
  （实机 1.01/1.04/1.43；官方 `GetBootVersion` 的 /10 那套实机不走）。
  `[103]` 探头路数 / `[104]` mosNum / `[105]` balaNum —— **三个独立字段，禁止相加**。
- **45B 帧(`0x00F0`)实测几乎全 0**，不含 SN 也不含「低压待机」`LVI`。官方 `decodeFrameB4` 说
  SN 在 `[20..35]`、LVI 在 `[20]`，起点重叠不可能并存 → 反编译还原错误，**不猜偏移**。
- 每个阈值独立量纲校验，读不到/离谱留 0（判「未知」不判「正常」）；总压阈值用**串数当标尺**（n×1.5~n×4.5V）。
- 告警统一模型：有独立阈值的一律「实测 vs 阈值」物理判定，硬件位只兜底无阈值类
  （欠压关断/SOC 异常/采样失效/执行器失效）。
- **官方 APP 截图是最理想的验证物**（已是除完系数的显示值），用户发截图时主动逐项对账。
- 启动零扫描：读 SP `bt_device_address` 直接 connectGatt，扫描只在用户点开设备列表时发生。
  `connectGatt(ctx,false,cb,**2**)` 显式 LE、不传 handler，固定 1000ms×4 次重试（不是指数退避）。
- 后期 TPMS：`BleManager` 是单连接设计（currentDevice/重连 job/ConnectionState 单实例），第二台必须
  另起实例或泛化；外置 TPMS 多为广播式（不占连接数），少数连接式需独立 GATT；抢射频沿用 `scanMutex`。

## 方法论（踩坑最多的地方）

1. **数值反常时分子分母都要查**；**别用算术复现替代代码级求证**（复现只证明假设自洽）。
2. **「实测读到 0」不能证明偏移对**：0 是不参与量纲校验的**吸收态**，错位/错系数/错字节序都产出 0。
   `if (v <= 0) return 0f` 会把「无数据/配置缺失/我算错了」全吞掉。防御写法：**上限校验保留**，
   下限改打日志暴露。量程上限也要按实测量级留余量（`SANE_CUR_MAX=500` 曾吞掉 888A，
   短路电流已单设 `SANE_SC_CUR_MAX=2000`）。
3. **jadx 的强转不可信，实机原始字节才是 ground truth**（`(short) byte2shortB` 可能只用低字节）。
   定位手段：临时加一行原始字节转储，编译一次看全部偏移（已三次靠它翻盘，是标准动作）。
4. **算能量绝不能用瞬时电压**（工况量），标称电压才是物性量；Wh/电量/续航一律取
   `BmsRealtimeData.nominalTotalVolt`（串数×类型标称电压）。
5. **余量类派生量按「净」算**：`energyPer100Km` 用「放电−回收」而非放电总量。
6. **用累计量差反推总量时分母要有下限**：SOC 是 u8（1% 一跳）且 BMS 有 ±2~3% 误差，跨度太小
   容量能偏 40%+ —— 要求 SOC 下降 ≥30%，且 SOC 上升（插充电器）时**必须重置起点**。
7. **无数据时看不到某元素是正常的**，截图分不清「改对了」和「根本没数据」。
   解法：造能看见真相的地方（诊断面板），或把判据抽成**纯 JVM 函数 + 单测**。别靠猜自证。
8. **界面只呈现「本机实测值」，禁止混入第三方参照值**（曾写「正常 3.9V」「官方 75A」被明确否决）。
   读不到的项**整项不出现**，连 `--` 占位都不许；标题不许带「与官方对账」这类内部措辞。
   ⚠️ 与悬浮窗行区分：悬浮窗无数据时**保留项目名、数值留白**，不能整行抹掉。
9. **数据留着 ≠ 要给人看**：485/CAN 协议解析保留但不展示。选展示项先问「用户拿这个干什么」。
   ⚠️ 反过来**告警/异常必须给判据**：只列总压/电流/SOC 用户仍不知在警告啥。正解每项一行
   「实测 X ＞/＜ 本机阈值 Y」+ 相关读数（`util/AlarmDetail.kt`）；一帧多条告警**合并成一个弹窗**。
10. **BLE 服务发现会先给未就绪的 GATT 缓存表**（华为实测：`onServicesDiscovered(SUCCESS)` 但特征列表空）。
    找不到 notify/write 先重跑 `discoverServices()`，并在**全部服务**里按特征 UUID 找。
    内部调试串（「特征值不匹配 write=...」）**绝不弹给用户**，只写 log。
    连接中的 GATT 上不要调 `refreshDeviceCache()`（必须 GATT 关闭后调，华为上易 ANR）。
11. **复位状态 ≠ 归零**，要还原成原始值（padding/scrollY/visibility 成组考虑）；
    手势语义不同才用 GestureDetector，View 显式 `isClickable=true`，`setOnTouchListener` 返回 `false`
    才能滚，容器也要绑手势。
12. **同症状连修两次没好 → 停止推测，去抓图量数据**（`ImageChops.difference`）；
    阈值按物理量纲估算，不能所有量共用"看起来很小"的值。
13. **用户说「增加到 N 个」是总数 N**，不是「再新增 N 个」。
14. 实机测试后**还原 SharedPreferences**（温度名、悬浮开关、位置、排序、TPMS 时间戳、测试颜色），
    并确认悬浮服务恢复运行 —— 改用户偏好是最容易被忽略的副作用。
